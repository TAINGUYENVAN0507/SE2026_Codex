# FE-05 — Upload và chống request trùng

Owner: member A · cập nhật: 22/10/2026.

## Giới hạn file

Frontend validate file theo `UploadConfig` (`max_upload_mb` và
`allowed_extensions`). Bản demo hiện dùng cấu hình mặc định 200 MB và danh sách
đuôi audio được hỗ trợ; đây là giá trị tạm cho đến khi backend cung cấp
`GET /api/v1/config`. Kích thước ghi âm, phần mô tả định dạng và thông báo lỗi
đều lấy từ cùng cấu hình.

Kiểm thử: `src/features/audio/validation.test.ts` bao phủ file rỗng, quá dung
lượng, đuôi không hỗ trợ, đuôi viết hoa và file hợp lệ. API config thật vẫn
đang chờ backend; Idempotency-Key đã được gửi ở bước upload.

## Khóa chống request trùng

`useIdempotencyKey(file)` sinh UUID cho file đang chọn. Giữ nguyên cùng object
`File` thì giữ khóa qua rerender/retry; chọn file khác sẽ sinh khóa mới; bỏ
chọn file trả về `null`. Hook cấp khóa cho header `Idempotency-Key` khi upload.

Kiểm thử `useIdempotencyKey.test.ts` xác nhận cả ba hành vi.

## Upload qua XHR

`uploadMeeting` gửi multipart với `file`, `title`, `meeting_date`, `source`,
`consent_confirmed=true` và header `Idempotency-Key`. XHR báo tiến độ và cho
phép hủy. Retry cùng file giữ khóa cũ. Lỗi HTTP được đổi thành `ApiError` để
trang upload hiển thị thông báo tiếng Việt; chỉ khi nhận 201 hợp lệ mới chuyển
đến trang chi tiết. MSW trả `meeting_created.json` trong bản xem thử.

`uploadMeeting.test.ts` dùng XHR giả để kiểm tra tiến độ, hủy, retry và các mã
lỗi 400/409/413/415/422. `NewMeetingPage.test.tsx` kiểm tra ở mức giao diện:
hủy upload không chuyển trang, retry giữ nguyên khóa và từng mã lỗi hiện đúng
thông báo tiếng Việt.
