# FE-05 — Upload và chống request trùng

Owner: member A · cập nhật: 22/10/2026.

## Giới hạn file

Frontend validate file theo `UploadConfig` (`max_upload_mb` và
`allowed_extensions`). Bản demo hiện dùng cấu hình mặc định 200 MB và danh sách
đuôi audio được hỗ trợ; đây là giá trị tạm cho đến khi backend cung cấp
`GET /api/v1/config`. Kích thước ghi âm, phần mô tả định dạng và thông báo lỗi
đều lấy từ cùng cấu hình.

Kiểm thử: `src/features/audio/validation.test.ts` bao phủ file rỗng, quá dung
lượng, đuôi không hỗ trợ, đuôi viết hoa và file hợp lệ. API config thật vẫn
đang chờ backend; Idempotency-Key đã được gửi ở bước upload.

## Khóa chống request trùng

`useIdempotencyKey(file, requestIdentity)` sinh UUID cho file và payload đang chọn. Cùng file, tiêu đề đã trim, ngày và nguồn thì giữ khóa khi retry; đổi file hoặc metadata sẽ sinh khóa mới; không có file trả null. Từ 25/11, trang tạo cuộc họp truyền identity của metadata để không dùng khóa cũ cho ngày đã sửa. Kiểm thử hook xác nhận cả đổi ngày và retry cùng payload.

## Upload qua XHR

`uploadMeeting` gửi multipart với `file`, `title`, `meeting_date`, `source`,
`consent_confirmed=true` và header `Idempotency-Key`. XHR báo tiến độ và cho
phép hủy. Retry cùng file và payload giữ khóa cũ. Lỗi HTTP được đổi thành `ApiError` để
trang upload hiển thị thông báo tiếng Việt; chỉ khi nhận 201 hợp lệ mới chuyển
đến trang chi tiết. MSW trả `meeting_created.json` trong bản xem thử.

`uploadMeeting.test.ts` dùng XHR giả để kiểm tra tiến độ, hủy, retry và các mã
lỗi 400/409/413/415/422. `NewMeetingPage.test.tsx` kiểm tra ở mức giao diện:
hủy upload không chuyển trang, retry giữ nguyên khóa và từng mã lỗi hiện đúng
thông báo tiếng Việt.


## Ngày họp bị từ chối (422) — 25/11/2026

Parser giữ danh sách `error.details` của FastAPI. Khi vị trí lỗi có `meeting_date`, form tự mở Tùy chọn cuộc họp, hiện lỗi tiếng Việt ngay cạnh ngày, gắn aria-invalid và aria-describedby. Tên truy cập của ô vẫn là Ngày họp. Không hiển thị message thô từ máy chủ.

Backend có thể trả VALIDATION_ERROR không kèm details khi ngày không tồn tại. Trường hợp này hiện lời nhắc kiểm ngày và tiêu đề cạnh ô ngày, không khẳng định riêng ngày sai (aria-invalid=false). Lỗi có vị trí trường khác vẫn dùng thông báo chung. Sửa ngày xóa lời nhắc; sửa tiêu đề chỉ xóa lời nhắc không xác định trường.

File và tiêu đề vẫn được giữ sau 422, không chuyển trang hoặc tự gửi lại. Sau khi sửa ngày, request dùng key mới; retry/hủy hoặc 503 với payload giữ nguyên vẫn dùng key cũ. `MeetingDateRejected.test.tsx` dùng MSW qua adapter FetchXHR kiểm hai dạng details, file/title, multipart ngày mới, khóa mới và chỉ tạo một meeting sau lần thành công. Đây là test UI/jsdom, không phải bằng chứng chạy browser với API thật cho trường hợp 422.

Bốn regression đỏ trước sửa: hai UI, một parser bỏ mất details và một hook không đổi key theo metadata. Sau sửa, nhóm upload/parser/hook đạt 33 test/6 file, không skip. Lint không warning và TypeScript đạt. Log UTF-8 tại `docs/evidence/final/frontend-meeting-date-{red,green}-2026-11-25.log`.


## Memo chỉ giữ khóa — 27/11/2026

useIdempotencyKey trả thẳng primitive từ useMemo, bỏ object identity/key không dùng. Dependency vẫn gồm file và requestIdentity: payload đổi phải cấp key mới dù callback chỉ đọc file. Có chú thích FE-05 và tắt riêng cảnh báo exhaustive-deps ở đúng dòng dependency vì đây là dependency chủ ý, không tắt rule toàn file.

Sáu test hợp đồng đạt trước refactor: retry giữ key; đổi title/date/source tạo key mới rồi retry payload đó giữ key; đổi File tạo key mới; bỏ file trả null. Sau refactor, nhóm hook/login/upload 28 test/4 file đạt, 0 skipped; lint không warning và TypeScript đạt. Log hợp đồng và hồi quy trong docs/evidence/final được ghi cùng đợt 27/11. Không đổi API của hook hoặc cơ chế chống gửi trùng.

Log hợp đồng trước/sau refactor: docs/evidence/final/frontend-idempotency-refactor-2026-11-27.log.
