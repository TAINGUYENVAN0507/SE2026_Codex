# FE-17 — Kiểm thử E2E trên stack thật

## Phạm vi

Chromium chạy frontend bản build qua Vite preview, proxy tới FastAPI thật,
PostgreSQL 16 riêng và worker với `PIPELINE_BACKEND=fake`. Không dùng MSW,
không chặn API để trả fixture, không gọi model AI hoặc dịch vụ bên ngoài.

## Chạy trên máy

Cần Node theo `frontend/.nvmrc`, uv, Python 3.12, PostgreSQL 16 và ffmpeg/ffprobe.
Tạo database riêng có tên chứa `e2e`; script từ chối tên khác để tránh seed nhầm
database phát triển. Không dùng dữ liệu người dùng thật.

```bash
cd frontend
npm ci
npx playwright install chromium
export E2E_DATABASE_URL=postgresql+psycopg://postgres:postgrespassword@127.0.0.1:5432/meeting_e2e
export SEED_DEMO_PASSWORD=local-e2e-demo-only-password
FAKE_SCENARIO=slow npx playwright test
FAKE_SCENARIO=permanent npx playwright test
FAKE_SCENARIO=transient_once npx playwright test
FAKE_SCENARIO=summary_fail npx playwright test
```

PowerShell dùng `$env:E2E_DATABASE_URL='...'`, `$env:SEED_DEMO_PASSWORD='...'`,
`$env:FAKE_SCENARIO='slow'`, sau đó `npx playwright test`.
Nếu uv chưa có trong PATH, đặt `UV` tới executable. `FFPROBE_BIN` có thể trỏ
tới ffprobe nếu chưa có trong PATH.

Playwright tự gọi `e2e/start-stack.sh` (Linux/macOS) hoặc cùng bộ khởi chạy
`e2e/stack.mjs` (Windows): sync backend theo lockfile, migrate, seed, build,
chạy API ở 18000, worker và preview ở 14173. Các cổng này phải trống.
Database do người chạy cung cấp; script không xóa database. Tiến trình do
script tạo được dừng khi kiểm thử kết thúc. Audio/artifacts tổng hợp dùng
storage mặc định `backend/appdata/`, không commit.

## CI

`.github/workflows/e2e.yml` dùng PostgreSQL service riêng, cài Chromium và
ffmpeg, chạy ma trận `slow`, `permanent`, `transient_once`, `summary_fail`.
Lỗi thì tải trace và screenshot lên artifact trong 7 ngày. Không dùng retry
của Playwright để che lỗi chập chờn. Chưa push thì chưa có bằng chứng CI.

## Các test đã viết

| Kịch bản | Kiểm tra |
|---|---|
| `slow` | Login demo qua cookie; upload WAV sinh trong RAM, đủ 6 stage thành công, transcript và player; RT-11 reload lúc running, giữ job id và không POST thêm meeting/job |
| `slow`, PRIV-01…09 | Consent và số lần gọi micro, indicator/timer, stop mọi track, bỏ bản ghi khi hủy, chỉ POST khi click tạo biên bản, cảnh báo reload, từ chối quyền, cleanup khi rời trang |
| `permanent` | Meeting failed, mã AUDIO_INVALID được đổi sang tiếng Việt, không hiện message kỹ thuật của fake pipeline |
| `transient_once` | Retry_scheduled với next_run_at thật, countdown giảm rồi lượt 2 thành công |
| `summary_fail` | Meeting partial, sửa segment qua PATCH thật và reload giữ nội dung |

Các test chờ trạng thái UI hoặc response API, không dùng `waitForTimeout`.
PRIV-08 tiêm phản hồi từ chối ở wrapper `getUserMedia`; các test ghi âm khác
dùng MediaRecorder thật với thiết bị audio giả của Chromium. Chữ “Tạo biên bản”
trên giao diện hiện tại là thao tác upload mà yêu cầu PRIV-06 gọi “Tải lên”.

RT-11 kiểm soát mọi POST từ trình duyệt và so sánh `latest_job_id` do server
trả về trước/sau reload; không truy cập DB từ frontend. Ràng buộc một job
active của DB vẫn thuộc test backend.
