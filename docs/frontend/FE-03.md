# FE-03 — Đăng nhập qua API và bảo vệ route

Owner: member A · cập nhật 24/10/2026.

## Đã làm

Các route cuộc họp lấy phiên bằng `GET /auth/me`. Khi chưa đăng nhập, app
chuyển tới `/login?next=<đường dẫn hiện tại>`; sau khi đăng nhập, điều
hướng quay lại đường dẫn đó. `safeNext()` chỉ cho phép đường dẫn nội bộ bắt đầu
bằng một dấu `/`, đồng thời chặn `//`, URL ngoài, `javascript:`, dấu gạch chéo
ngược và dấu `/` mã hóa.

`LoginPage` gọi `POST /auth/login` với cookie cùng origin. Không lưu mật khẩu
hoặc token vào Web Storage. 401 hiển thị thông báo sai email/mật khẩu, giữ email
và xóa mật khẩu khỏi form. Lỗi mạng hiển thị thông báo riêng. Nút gửi bị khóa
trong lúc chờ. `useMe` trả phiên hoặc null; lỗi kết nối không bị coi là chưa đăng nhập.

Kiểm tra: unit test cho đường dẫn hợp lệ và các giá trị không an toàn; test
React Testing Library kiểm tra đăng nhập thành công, sai mật khẩu, lỗi mạng,
khóa nút khi chờ, không ghi Web Storage và quay về đường dẫn an toàn.

Trong lúc lấy phiên, route hiển thị skeleton. 401 từ client API hoặc upload XHR
kết thúc phiên, hủy request, xóa query cache và đưa về login kèm next. Nút đăng xuất
gọi `POST /auth/logout`, sau đó xóa cache và dữ liệu xem thử trong bộ nhớ.
Đăng xuất lỗi mạng thì giữ phiên để người dùng có thể thử lại.
`Session.test.tsx` kiểm tra skeleton, redirect, phiên hợp lệ, cache sau logout,
401 ở API khác và lỗi mạng khi logout.
