## 1. [P2] Không bắt AssertionError của phép kiểm canary trên file

Vị trí: `backend/tests/privacy/test_privacy_canary.py:187–193`.

`assert canary.encode(...) not in raw_bytes` nằm trong `try`, còn
`except Exception: pass` bắt luôn `AssertionError`. Vì vậy nếu file còn dữ liệu
canary sau xóa, phép kiểm vẫn kết thúc thành công. Lỗi đọc file cũng bị bỏ qua,
không chứng minh được storage đã sạch như mô tả test.

Đã kiểm chứng bằng cách tạo một file tạm chứa đúng `CANARY_TITLE`, rồi gọi
`_assert_no_canaries_in_storage(...)`: hàm **không báo lỗi**.

Đề nghị: để assertion ngoài khối bắt lỗi; lỗi đọc file phải làm test fail hoặc
được xử lý rõ ràng. Thêm negative control: cố tình giữ file có canary thì helper
phải ném `AssertionError`. Với test xóa, xác nhận canary thực sự có trên đĩa
trước thao tác xóa để tránh kiểm trên dữ liệu chưa từng tồn tại.

## 2. [P2] Canary của test lỗi worker chưa đi vào exception message

Vị trí: `backend/tests/privacy/test_privacy_canary.py:446–467`.

Test `test_privacy_canary_worker_internal_failure_does_not_log_error_data` tạo
canary trong tiêu đề meeting, nhưng exception giả chỉ có message cố định
`Audio format cannot be decoded`. Vì vậy test không phát hiện việc nội dung
exception có dữ liệu người dùng bị ghi vào log, dù tên và mô tả đang nói tới
nhánh lỗi worker/pipeline.

Đã kiểm chứng trên **bản sao test riêng**, chỉ thay message của exception bằng
`CANARY_JOB_TITLE_FAILURE_LEAK_CHECK`: test fail ở phép kiểm log. Worker đang
log trực tiếp `err` tại `backend/app/worker/runner.py:415–418`, khiến message
canary xuất hiện trong log.

Đề nghị: đưa canary vào exception message, kiểm cả log và thông điệp trả ra
API nếu thuộc phạm vi test; sửa nhánh log để chỉ ghi metadata/mã lỗi an toàn.
Nhánh worker log này đã có trên main, không phải regression do tách controller;
điểm cần sửa trong PR là test mới chưa bắt được trường hợp dữ liệu nằm trong lỗi.
Không dùng kết quả test hiện tại để khẳng định exception không thể làm lộ dữ liệu.

## 3. Lỗi nền cần phối hợp: Docker Web build đạt nhưng không khởi động

chỉ thay `/var/run/nginx.pid`, trong khi image `nginx:1.27-alpine` đang dùng
`/run/nginx.pid`. Khi chuyển sang user `nginx`, container không ghi được PID.

Đã build đúng snapshot PR thành image `se-pr41-web-review:489f9e0`, sau đó chạy:

```powershell

```

Chạy CMD mặc định trong container riêng cũng exit 1, `Running=false`.
Workflow Docker hiện chỉ build và liệt kê image, nên CI xanh không bắt lỗi này.

**Lỗi này đã có trên main trước PR #41.** Nhánh `vantuong` có bản sửa local
`36b1af4` (đổi directive PID sang `/tmp/nginx.pid`, build và smoke test đã đạt).
Cần thống nhất bản sửa khi tích hợp, không chép đè công việc của nhau hoặc quy
